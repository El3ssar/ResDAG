    The common model workflow¶

    rd.Model adds training, scaling and forecasting around a functional graph. It is an ordinary PyTorch module. You keep control of the layers, their initializers and the readout solver.

    Inputs are floating Torch tensors shaped (time, features) or (batch, time, features), on the same device and dtype as the graph. Named multi-input data uses a dictionary of those tensors. rd.ESN provides the same Torch workflow for a ready-made classic reservoir. Convert NumPy arrays with torch.as_tensor at the boundary. fit and forecast also accept TSDynamics trajectories, including named trajectories for several ports. Ordinary model(x) calls retain the tensor interface.

    This is part of phase two. The common interface supports the ESN preset, symbolic, parallel and coupled graphs. Raw ESNModel and factories remain useful building blocks. Unified tuning is available for presets and custom DAGs. Complete model saves, automatic loading and diagram exports are available through the same interface.

    Build, fit and forecast¶

    The inputs are named signals. The outputs are named predictions. Connect layers with layer(x), then give those connections to rd.Model.

    import torch
import resdag as rd

# A small example with two signals in different physical units.
t = torch.arange(400, dtype=torch.float64) * 0.05
series = torch.stack((10 + 2 * t.sin(), -3 + 0.5 * t.cos()), dim=-1)
train, truth = series[:300], series[300:340]

x = rd.reservoir_input(2, dtype=torch.float64)
h = rd.ESNLayer(64, feedback_size=2, seed=7, dtype=torch.float64)(x)
y = rd.SVDReadoutLayer(64, 2, alpha=1e-6).double()(h)
model = rd.Model(inputs={"state": x}, outputs={"prediction": y}, washout=30)

model.fit(train)
prediction = model.forecast(history=train[-60:], horizon=40)
assert prediction.shape == truth.shape
assert torch.isfinite(prediction).all()

    For one input and one output of the same width, fit(train) learns to predict the next sample. It uses the first washout samples to synchronize the reservoir, then fits the readout. Pass only training data to fit; keep validation and test samples separate.

    Standard scaling is automatic. Its statistics come from the supervised training inputs, excluding washout and the final shifted target. Forecasts are returned in the signals' original units. The first forecast sample estimates the sample immediately after the supplied history.

    Omit history to continue from the saved tail of the training data. Supplying history resynchronizes the reservoir on that history before forecasting. Choose preprocessing=None to handle scaling yourself, or choose an existing normalization method: "standard", "minmax", "noncentered" or "meanpreserving".

    Override individual ports with input_transforms={"state": your_module} and output_transforms={"prediction": your_module}. Each module preserves the signals and provides a reversible change of units. Use a distinct instance for each port; torch.nn.Identity() disables preprocessing on one port. Explicit overrides still apply when the global policy is off. See custom preprocessing for a complete example, fitting rules and checkpoints. Operations that add features or memory belong inside the DAG as ordinary layers.

    Use a preset graph¶

    For the ready-made vanilla model, choose its readout features explicitly:

    state_only = rd.ESN(
    reservoir_size=64, input_size=2, input_to_readout=False,
    washout=30, readout="svd", seed=7, dtype=torch.float64,
).fit(train)
state_only_prediction = state_only.forecast(horizon=40)
assert state_only_prediction.shape == truth.shape

    The default input_to_readout=True gives the head both reservoir memory and the current input. False gives it reservoir memory alone. model.tune() tries both for an unmodified vanilla recipe. A custom DAG can connect either set of features directly; OTT's augmented features keep their own wiring.

    Wrap a factory-built graph with the same model interface:

    graph = rd.classic_esn(
    reservoir_size=64, feedback_size=2, output_size=2,
    readout="svd", seed=7, dtype=torch.float64,
)
preset = rd.Model(graph=graph, washout=30)
preset.fit(train)
preset_prediction = preset.forecast(history=train[-60:], horizon=40)
assert preset_prediction.shape == truth.shape

    model.graph gives access to the exact underlying graph and its parameters. It works in the graph's raw, preprocessed units. Use model(...) when your pipeline supplies and expects the original units.

    Parallel and coupled models¶

    The same wrapper works for a spatial field split into overlapping patches:

    parallel = rd.Model(
    graph=rd.parallel_esn(
        input_dim=2, core_width=1, halo=1, reservoir_size=32,
        readout="svd", seed=7, dtype=torch.float64,
    ),
    washout=30,
)
parallel.fit(train)
parallel_prediction = parallel.forecast(history=train[-60:], horizon=40)
assert parallel_prediction.shape == truth.shape

    Inputs and returned predictions use the full field width. Scaling is learned per field component, before the backend gathers local patches. Each patch keeps its own recurrent state; reservoir and readout weights remain shared.

    For an ensemble whose members share one aggregate feedback signal:

    coupled = rd.Model(
    graph=rd.coupled_ensemble_esn(
        n_models=3, model_factory=rd.classic_esn,
        reservoir_size=32, feedback_size=2, output_size=2,
        readout="svd", seed=7, dtype=torch.float64,
    ),
    washout=30,
)
coupled.fit(train)
coupled_prediction = coupled.forecast(history=train[-60:], horizon=40)
assert coupled_prediction.shape == truth.shape

    The coupled backend retains its existing single aggregate output. Each member fits its own head, even when internal readout names differ. Inspect individual member forecasts through coupled.graph; the common workflow returns the aggregate. Parallel and coupled forecast currently require compile=False. Unsupported compiled forecasts fail before running the graph.

    Both families use the same original-unit forward calls, carried state, explicit-state calls, dtype/device moves and state dictionaries as symbolic graphs. Rebuild the same architecture before loading a state dictionary, including custom aggregator settings. Its schema checks structural facts, not arbitrary Python configuration. Use model.save("run.pt") and rd.load("run.pt") for complete architecture reconstruction; see save and load.

    Give several heads explicit targets¶

    Name each output and pass matching targets. Explicit targets line up with the supplied input samples; fit does not shift them. Here we supply that shift ourselves and add a second quantity to predict:

    state = rd.reservoir_input(2, dtype=torch.float64)
features = rd.ESNLayer(32, feedback_size=2, seed=11, dtype=torch.float64)(state)
position = rd.SVDReadoutLayer(32, 2, alpha=1e-6).double()(features)
energy = rd.SVDReadoutLayer(32, 1, alpha=1e-6).double()(features)
multi = rd.Model(
    inputs={"state": state},
    outputs={"position": position, "energy": energy},
    washout=30,
)
next_state = train[1:]
multi.fit(
    {"state": train[:-1]},
    targets={
        "position": next_state,
        "energy": next_state.square().sum(dim=-1, keepdim=True),
    },
)
named = multi({"state": train[-20:]})
assert named["position"].shape == (20, 2)
assert named["energy"].shape == (20, 1)

    Each target gets its own training-only scaling. The user-facing output names do not need to match the graph's generated readout names. Feedback converts the selected prediction through original units before applying the receiving input's scaling. See feedback and timing for named connections, delays and predicting several samples ahead.

    Put the trained model inside PyTorch¶

    model(x) returns a tensor for a single output, preserves gradients and carries reservoir state between calls. Reset before starting an unrelated sequence. train() and eval() do not reset that state.

    from torch import nn

pipeline = nn.Sequential(
    nn.Linear(2, 2, dtype=torch.float64),
    model,
    nn.Linear(2, 1, dtype=torch.float64),
)
model.reset_state()
batch = train[-20:].unsqueeze(0).detach().requires_grad_()
loss = pipeline(batch).square().mean()
loss.backward()
assert batch.grad is not None
assert torch.isfinite(batch.grad).all()

    Frozen reservoir weights still pass gradients to the preceding layer. Stored reservoir state follows the layers' existing detach policy at call boundaries. For explicit streaming state and gradients across chunks, use prediction, state = model.forward_stateless(chunk, states=previous_state). That path leaves stored reservoir state unchanged.

    Move the complete model with ordinary .to(device) or .double() calls; fitted scaling statistics move with it. Scaling and the graph are included in state_dict(). As with ordinary PyTorch checkpoints, loading a state dict still requires a compatible model architecture. Use model.save("run.pt") and rd.load("run.pt") to restore a complete model without rebuilding its graph; see save and load.

    On Apple MPS, AutoReadoutLayer uses supported float32 operations when its numerical checks pass. Unsafe or unsupported decompositions use a reported, configurable CPU float64 bridge. You can also fit on CPU and move the model with model.float().to("mps"). See solver controls.

    Train the surrounding network¶

    After fitting the RC block, ordinary Torch optimizers can train the encoder and prediction head. The reservoir and algebraically fitted readout stay frozen unless you explicitly make them trainable. Construct the optimizer after fitting or building the model, so every parameter is registered.

    Reset the reservoir before unrelated training windows. Calls otherwise carry memory, with gradients detached at each ordinary call boundary. For gradients across chunks of one sequence, use forward_stateless(..., states=...) and carry the returned state yourself.

    The following uses standard PyTorch mixed precision and gradient scaling:

    import copy

amp_device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
amp_pipeline = copy.deepcopy(pipeline).to(device=amp_device, dtype=torch.float32)
amp_optimizer = torch.optim.Adam(amp_pipeline.parameters(), lr=1e-3)
amp_scaler = torch.amp.GradScaler("cuda", enabled=amp_device.type == "cuda")
amp_dtype = torch.float16 if amp_device.type == "cuda" else torch.bfloat16
amp_batch = train[-20:].unsqueeze(0).to(device=amp_device, dtype=torch.float32)
amp_target = amp_batch[..., :1]

for _ in range(2):
    amp_pipeline[1].reset_state()
    amp_optimizer.zero_grad(set_to_none=True)
    with torch.autocast(amp_device.type, dtype=amp_dtype):
        amp_prediction = amp_pipeline(amp_batch)
        amp_loss = torch.nn.functional.mse_loss(amp_prediction.float(), amp_target)
    amp_scaler.scale(amp_loss).backward()
    amp_scaler.step(amp_optimizer)
    amp_scaler.update()

    CPU CSR multiplication has no low-precision kernel. Under CPU autocast, a sparse ESN therefore computes its recurrent multiplication and carried state in its stored weight precision; the surrounding encoder and head still use autocast. No tensor moves to another device for this operation. Explicitly stored low-precision CSR weights still require a matching supported Torch kernel.

    Standard torch.compile(pipeline) is separate from the reservoir forecast's compile=True shortcut. The surrounding network's forward and backward can be captured together; ordinary calls still detach stored state between calls. The forecast shortcut remains inference-only. Full-graph capture and compiled backward are tested for the built-in vanilla, OTT and named custom DAG examples with the AOT eager backend. This checks compiler compatibility, not CUDA throughput. Measure cold setup and warm execution on your actual device and check forecast accuracy when changing precision.

    Capture the surrounding pipeline with FX¶

    If a larger pipeline uses PyTorch FX, keep the reservoir as one module call. Use FX's standard leaf-module hook:

    from torch import fx

class ReservoirTracer(fx.Tracer):
    def is_leaf_module(self, module, qualified_name):
        return isinstance(module, (rd.Model, rd.ESN)) or super().is_leaf_module(
            module, qualified_name
        )

captured = fx.GraphModule(pipeline, ReservoirTracer().trace(pipeline))
assert captured.get_submodule("1") is model
model.reset_state()
expected = pipeline(batch.detach())
model.reset_state()
actual = captured(batch.detach())
torch.testing.assert_close(actual, expected)

    Capture preserves the same model, parameters and carried state. It does not execute the reservoir during tracing. Direct tracing through rd.Model and general deployment export are not supported; see the graph-tooling review for the evaluated boundaries.

    Current boundaries¶

    • The common wrapper supports symbolic ESNModel, ParallelESNModel and CoupledEnsembleESNModel graphs. Their original low-level APIs remain available.
    • Automatic next-sample targets require one unambiguous input/output pair. Several heads need explicit named targets; their predictions are returned as a dictionary. Internal fitted readouts can stay hidden from predictions: provide their targets through fit(..., readout_targets={...}), as shown in training internal readouts.
    • Default feedback connects the first output to the first input. Custom named routes support fanout and explicit delays. Inputs without a feedback route need future driver values.
    • Reservoirs must be separate functional nodes for explicit-state and forecast execution. See state management.
    • Forecasting and explicit-state calls honor PyTorch execution hooks, including hooks on the model, reservoir, nested modules and global hook registrations. Input/output hooks on Model or ESN operate in the original signal units. Adding or removing hooks takes effect on the next call; hook-free models keep the lean flat forecast path. Hooks select an eager compatible path, with a warning when compile=True was requested.
    • Fast forecasting requires framewise operations or explicit reservoir nodes. Custom sequence operations can use history execution, which replays their full growing prefix. Delayed/named feedback uses explicit state; reservoir state alone cannot resume an in-progress delayed rollout.
    • Fitting stages a copy of the graph before committing trained weights. This preserves the existing model after a failed fit and keeps parameter objects intact, but requires memory for that temporary copy and the solver workspace.

    See the core reference for signatures and the phase-two design note for agreed behavior and remaining decisions.
